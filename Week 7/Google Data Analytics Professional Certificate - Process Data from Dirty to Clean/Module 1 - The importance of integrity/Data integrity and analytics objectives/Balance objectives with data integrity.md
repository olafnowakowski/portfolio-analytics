# Aligning Data With Business Objectives

## Main Idea

Checking data integrity is important, but Data Analysts also need to make sure the data they use aligns with the business objective.

Even if data is accurate and clean, it may not be useful if it does not answer the business question.

---

# 1. Why Data Must Match the Business Objective

Data analysis should always connect back to the business problem or objective.

Before starting analysis, ask:

- What question am I trying to answer?
- What business objective does this support?
- Which data table or dataset is relevant?
- Does the data contain the information needed?
- Are there any limitations in the data?

Using the wrong data can lead to analysis that is technically correct but not useful for the business.

---

# 2. Example: Auto Parts Business

Imagine you are an analyst for a company that produces and sells auto parts.

If the business question is about revenue generated by a certain part, you should use the **revenue table**.

If the business question is about customer reviews, you should use the **reviews table**.

## Key Lesson

Different business questions require different data.

You need to choose the dataset that matches the objective.

---

# 3. Data Limitations

Before analyzing data, check whether there are limitations that could affect your results.

Common limitations include:

- data has not been cleaned
- duplicate data exists
- there is not enough data
- important fields are missing
- the available data does not fully answer the question

---

# 4. Unclean Data

If data has not been cleaned properly, it may not be ready for analysis.

Unclean data may contain:

- missing values
- duplicate records
- incorrect formats
- inconsistent entries
- invalid values
- errors from data entry or transfer

## Key Lesson

Do not begin analysis until the data is clean enough to use.

---

# 5. Duplicate Data

**Duplicate data** means the same data appears more than once.

For example, the same customer might appear in more than one row.

This can cause misleading calculations.

---

## Duplicate Data Example

If you are trying to calculate how much an average customer spends, duplicate customer records can create a problem.

Excel or a database may treat the duplicated customer as two different people.

This could make the average customer spend inaccurate.

---

## How to Handle Duplicate Data

To deal with duplicate data, you may need to:

- remove duplicate records
- change the format of the data
- group records by customer
- adjust the calculation method
- confirm whether records are truly duplicates before deleting them

---

# 6. Not Enough Data

Sometimes there is not enough data to complete an accurate analysis.

For example, if you only have a few months of sales data, it may not be enough to identify long-term trends.

---

## What to Do If There Is Not Enough Data

If the dataset is too limited, you may need to:

- wait for more data
- change the analysis process
- find alternate data sources
- adjust the scope of the analysis
- explain the limitation clearly

---

# 7. Incomplete Data and the “Whole Picture”

A dataset is like a picture.

If you only see part of the picture, it can be hard to understand what is really happening.

Incomplete data can hide important details and lead to incorrect conclusions.

## Key Lesson

Rows and columns can make data look complete, but that does not mean everything needed for analysis is actually there.

---

# 8. Real-World Example: Delivery Time

An analyst was asked to find ways to shorten the time between customer purchase and delivery.

Faster delivery usually leads to happier customers.

However, the dataset had limited tracking information and was missing key details.

---

## Problem

The available data did not include enough information about the delivery journey.

Important missing details included things like the number of stops in the delivery route.

---

## Solution

The analyst worked with data engineers to create new tracking processes.

These new processes collected additional information.

With better data, the company was able to reduce delivery time and improve customer satisfaction.

---

# 9. Data Engineers and Better Data Collection

Sometimes analysts need help from data engineers when the available data is not enough.

Data engineers can help create systems or processes to collect better data.

This supports stronger future analysis.

---

# 10. Staying Focused on the Objective

When data issues appear, analysts should not lose sight of the business objective.

Instead, they should ask:

- What data do I need to answer this question?
- What data do I actually have?
- What is missing?
- Can I find another data source?
- Do I need to change my method?
- Do I need help from data engineers?

---

# 11. Common Data Issues That Affect Business Objectives

| Data Issue | How It Affects Analysis |
|---|---|
| Unclean data | Data cannot be trusted until cleaned |
| Duplicate data | Calculations may count the same person or event more than once |
| Missing data | Analyst may not have the full picture |
| Limited timeframe | Trends may be inaccurate or incomplete |
| Wrong table selected | Analysis may not answer the business question |
| Missing tracking details | Analyst may be unable to explain what is happening |

---

# 12. Common Mistakes to Avoid

## Mistake 1: Using data without checking the objective

Always make sure the data matches the business question.

## Mistake 2: Assuming rows and columns mean the data is complete

A dataset may look organized but still be missing important information.

## Mistake 3: Ignoring duplicate records

Duplicate data can create misleading averages, totals, and counts.

## Mistake 4: Analyzing unclean data

Unclean data can lead to inaccurate conclusions.

## Mistake 5: Continuing without enough data

If there is not enough data, find another source, adjust the method, or explain the limitation.

---

# 13. Big Lesson

Data integrity is not only about whether the data is accurate and clean.

It is also about whether the data is appropriate for the business objective.

Good analysis requires both:

- trustworthy data
- relevant data

---

# Key Takeaways

- Data should align with the business objective.
- Different business questions require different datasets.
- Revenue questions need revenue data.
- Customer review questions need review data.
- Data limitations must be checked before analysis.
- Unclean data should be cleaned before use.
- Duplicate data can create misleading calculations.
- Not having enough data can limit the accuracy of analysis.
- Incomplete data makes it hard to see the full picture.
- Analysts may need alternate data sources or new data collection processes.
- Data engineers can help create better tracking systems.
- Staying focused on the business objective helps analysts handle data issues effectively.

---

# Final Summary

This lesson explains that Data Analysts must check both data integrity and alignment with the business objective. The data used in analysis should directly support the question being asked. For example, revenue questions require revenue data, while customer review questions require review data. Analysts must also consider data limitations, such as unclean data, duplicate records, missing information, or not enough data. Duplicate data can make calculations misleading, while incomplete data can prevent analysts from seeing the full picture. In some cases, analysts may need to find alternate data sources or work with data engineers to collect better information. The main lesson is that successful analysis depends on using data that is both trustworthy and relevant to the business objective.
