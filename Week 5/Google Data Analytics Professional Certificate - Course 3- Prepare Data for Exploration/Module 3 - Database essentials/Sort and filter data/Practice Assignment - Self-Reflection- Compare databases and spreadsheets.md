# Spreadsheets vs Databases

## Main Idea

Spreadsheets and databases both store and organize data, but they are used differently.

**Spreadsheets** are better for smaller, self-contained datasets.

**Databases** are better for larger, connected datasets that need relationships, structure, and powerful querying.

---

# Similarities Between Spreadsheets and Databases

Spreadsheets and databases can both be used to:

- store data
- organize data
- sort data
- filter data
- search data
- compare information
- support analysis
- help users make data-driven decisions

---

# Key Difference

The biggest difference is that **databases can be relational**, while spreadsheets cannot.

A relational database can connect multiple tables using shared fields, such as primary keys and foreign keys.

A spreadsheet usually stores data in one place, such as one sheet or workbook.

---

# Spreadsheet

## Definition

A **spreadsheet** is a tool that stores data in cells arranged in rows and columns.

Examples:

- Google Sheets
- Microsoft Excel

---

# Database

## Definition

A **database** is a system used to store, manage, and organize data.

A relational database stores data in related tables that can be connected.

Examples:

- SQL databases
- BigQuery
- MySQL
- PostgreSQL

---

# Comparison Table

| Question | Spreadsheets | Databases |
|---|---|---|
| **How is data stored?** | Data is stored in cells arranged in rows and columns. | Data is stored in tables made up of records and fields. |
| **How are they used to interact with data?** | Users can directly edit cells, use formulas, create charts, sort, and filter data. | Users interact with data through queries, tables, forms, reports, and database tools. |
| **How powerful are they?** | Best for smaller or simpler datasets. They are easy to use but less powerful for large or complex data. | More powerful for large datasets, connected data, multiple users, and complex queries. |
| **How do they handle relationships?** | Spreadsheets are usually self-contained and do not manage relationships between tables well. | Relational databases connect tables using primary keys and foreign keys. |
| **What are the pros of sorting data?** | Sorting is quick and easy for small datasets. Users can sort directly from the spreadsheet interface. | Sorting can be done on large datasets using queries and can be combined with other conditions. |
| **What are the cons of sorting data?** | Sorting can cause mistakes if users sort only part of the data and separate rows incorrectly. | Sorting requires knowledge of database tools or SQL, so it may be less beginner-friendly. |
| **What are the pros of filtering data?** | Filtering is simple and useful for quickly hiding rows that do not meet certain criteria. | Filtering is powerful and can handle large datasets, multiple conditions, and connected tables. |
| **What are the cons of filtering data?** | Filtering can become difficult with very large or complex datasets. | Filtering usually requires queries or database knowledge. |
| **When is it better to use?** | Best for quick, simple tasks, small lists, budgets, schedules, and one-time analysis. | Best for large, complex, shared, or connected datasets. |
| **Main advantage** | Easy to set up, easy to edit, and beginner-friendly. | More reliable, scalable, structured, and powerful for complex data management. |
| **Main limitation** | Can become messy, error-prone, or slow with large or connected datasets. | Requires more setup and technical knowledge. |

# When to Use a Spreadsheet

A spreadsheet is better when the task is simple and the data is small or self-contained.

## Good spreadsheet use cases

- creating a budget
- tracking assignments
- making a small list
- creating a simple report
- organizing one-time data
- making quick calculations
- building simple charts

---

# Why Use a Spreadsheet?

Spreadsheets are useful because they are:

- easy to set up
- easy to edit directly
- good for small datasets
- useful for quick analysis
- simple to share
- beginner-friendly

---

# When to Use a Database

A database is better when the data is large, complex, shared, or connected across multiple categories.

## Good database use cases

- customer relationship management
- inventory systems
- sales transaction records
- employee records
- large business datasets
- datasets used by many users
- data with relationships between tables

---

# Why Use a Database?

Databases are useful because they:

- handle large amounts of data
- reduce duplication
- support multiple users
- improve data integrity
- connect related tables
- allow powerful searching through queries
- keep data more organized over time

---

# Sorting in Spreadsheets

Sorting in spreadsheets is useful because it is quick and visual.

Examples:

- sort names alphabetically
- sort sales from highest to lowest
- sort dates from oldest to newest

## Risk

Sorting only one column instead of the full dataset can separate related data and cause errors.

---

# Sorting in Databases

Sorting in databases is usually done through queries.

This is powerful because analysts can sort large datasets and combine sorting with filters or joins.

## Example

A database query could sort customers by state, then city, then total sales.

---

# Filtering in Spreadsheets

Filtering in spreadsheets hides rows that do not meet selected criteria.

Examples:

- show only one product
- show only one region
- show only sales above a certain amount

## Benefit

Filtering is easy to apply from the spreadsheet interface.

---

# Filtering in Databases

Filtering in databases is usually done with queries.

This allows analysts to search large datasets using specific conditions.

## Example

A database query could show only customers in California who purchased more than $500 in products during the last quarter.

# Reflection Answers

## What similarities exist between spreadsheets and databases?

Spreadsheets and databases both organize information in rows and columns, making data easier to store, search, sort, filter, and compare.

Both can help users identify patterns, track changes, and make decisions based on organized information.

---

## What differences exist between spreadsheets and databases?

Spreadsheets are easier to set up and are often used for smaller, simpler tasks.

Databases are designed for larger amounts of connected data. They reduce duplication, support multiple users, and allow more powerful searching through queries and relationships between tables.

---

## When is a spreadsheet better?

A spreadsheet is better for quick, simple projects.

Examples:

- budget tracking
- assignment tracking
- simple lists
- small reports
- basic calculations

A spreadsheet works well when the data does not need complex relationships or many users.

---

## When is a database better?

A database is better when managing large amounts of data, especially when the data is shared by many people or connected across different categories.

Databases are better for storing, updating, and querying information because they reduce errors and keep related data organized.

# Big Lesson

Spreadsheets and databases are both useful tools, but they are designed for different situations.

Use a spreadsheet for simple, small, self-contained data.

Use a database for large, complex, connected, or shared data.

---

# Final Summary

Spreadsheets and databases both help users store, organize, sort, filter, and analyze data. Spreadsheets are easier to use and are best for smaller, simpler, self-contained datasets, such as budgets, schedules, or small lists. Databases are more powerful and are better for large, complex, connected datasets that involve multiple tables, relationships, and users. Databases can be relational, meaning they can connect tables using shared fields like primary keys and foreign keys. Sorting and filtering are available in both tools, but databases handle these tasks more powerfully through queries. The main lesson is that spreadsheets are best for quick and simple work, while databases are best for structured, scalable, and connected data management.
