# Data Tables, Records, Fields, and Values

## Main Idea

Many everyday tools organize information in tables.

Examples include:

- music playlists
- calendar agendas
- email inboxes
- spreadsheets
- databases

A table helps organize data into a clear structure so it is easier to read, search, and analyze.

---

# What Is a Data Table?

A **data table**, also called **tabular data**, is data arranged in rows and columns.

This structure helps organize data in a predictable way.

---

# Rows and Columns

In spreadsheets, people usually describe tables using:

- **rows**
- **columns**

In databases and data analytics, people often use:

- **records**
- **fields**

These terms are closely related.

---

# Records

## Definition

A **record** is one row in a data table.

It contains all the information about one item, person, event, or object.

---

## Playlist Example

In a music playlist, each song is a record.

Each song has information such as:

- song title
- artist
- album
- song length
- favorite status

Each song is one full record in the table.

---

# Fields

## Definition

A **field** is one column in a data table.

A field describes a specific characteristic or attribute of each record.

---

## Playlist Example

In a music playlist, fields could include:

- title
- artist
- album
- length
- favorite

Each field contains the same kind of information for every record.

---

# Values

## Definition

A **value** is a single piece of data inside a cell.

It is the actual data stored where a record and field meet.

---

## Playlist Example

If the field is **Artist** and the record is one specific song, the value might be:

**Taylor Swift**

If the field is **Length**, the value might be:

**3:45**

---

# Records, Fields, and Values Together

| Table Term | Spreadsheet Term | Meaning |
|---|---|---|
| **Record** | Row | One complete item in the table |
| **Field** | Column | A category or attribute of the record |
| **Value** | Cell value | One specific piece of data |

---

# Playlist Example

A playlist table might look like this:

| Title | Artist | Length | Favorite |
|---|---|---:|---|
| Song A | Artist 1 | 3:45 | TRUE |
| Song B | Artist 2 | 4:12 | FALSE |
| Song C | Artist 3 | 2:58 | TRUE |

In this table:

- each song is a **record**
- each column is a **field**
- each cell contains a **value**

---

# Same Fields for Each Record

Each record in a table usually has the same fields in the same order.

For example, every song in a playlist may have:

- title
- artist
- length
- favorite status

This consistency makes the data easier to organize and analyze.

---

# Fields Can Have Different Data Types

Each field usually contains one kind of data type.

Different fields can have different data types.

---

## Playlist Data Type Examples

| Field | Possible Data Type |
|---|---|
| Song title | Text or string |
| Artist | Text or string |
| Song length | Number or time |
| Favorite | Boolean |

---

# Text or String Fields

A field like **song title** is usually a text or string data type.

Examples:

- song title
- artist name
- album name

These are not used for mathematical calculations.

---

# Number or Time Fields

A field like **song length** may be stored as a number or time value.

This could be useful if you want to calculate:

- total playlist length
- average song length
- longest song
- shortest song

---

# Boolean Fields

A field like **favorite** may be Boolean.

Boolean data has only two possible values.

Examples:

- TRUE or FALSE
- favorite or not favorite
- yes or no

---

# Spreadsheet Examples

Spreadsheets can contain records about many things, such as:

- clients
- products
- invoices
- employees
- transactions
- songs
- events

Each record has several fields that describe it.

---

## Client Example

| Client Name | Address | Phone Number | Active Customer |
|---|---|---|---|
| Maria Lopez | 20 Oak Street | 555-0182 | TRUE |
| Jamal Reed | 8 Pine Road | 555-0199 | FALSE |

In this table:

- each client is a record
- each column is a field
- each cell contains a value

---

## Invoice Example

| Invoice ID | Client | Amount | Paid |
|---|---|---:|---|
| INV-1001 | Maria Lopez | 250.00 | TRUE |
| INV-1002 | Jamal Reed | 400.00 | FALSE |

In this table:

- each invoice is a record
- amount is a numeric field
- paid is a Boolean field
- client is a text field

# Why This Matters for Data Analysts

As a Data Analyst, you will work with many data tables.

Understanding records, fields, and values helps you:

- navigate tables
- understand data structure
- identify data types
- choose the right analysis method
- avoid confusion
- clean data correctly
- organize data effectively

---

# Data Table Structure

A good data table usually has:

- consistent fields
- one record per row
- one field per column
- one value per cell
- clear field names
- correct data types

---

# Big Lesson

Tables organize data into records, fields, and values.

This structure makes data easier to understand, manage, and analyze.
